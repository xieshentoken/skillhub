## 阶段 2：导入状态按真实版本判定（已完成）

### 问题与职责

新版 `static/js/imports.js` 只用 `source_paths` 判断“已在中央库”。来源路径不变而脚本内容变更时，仍会显示已导入。

- 后端 `webgui.py` 负责提供只读、可验证的版本身份：`/api/data` 的 skill 条目增加完整 `md5`；`/api/sources` 的有效来源增加 `import_sid`，复用 `store.skill_id_for(name, md5)` 计算真实导入目标。
- 前端 `static/js/imports.js` 负责根据这些字段展示状态；不得只比较名称、路径或摘要前八位，也不得对每行另发详情请求。
- 不修改 `store.import_skill` 的复制、候选版本、去重与来源合并行为，不引入新的索引字段或数据库。

实际契约：`/api/data` 的 `skills[].md5` 为完整 32 位摘要；`/api/sources` 的有效来源返回 `md5` 与 `import_sid`，单 agent 扫描失败保留为带原因的错误来源行。来源状态只在 `skill.id === import_sid` 且完整摘要相等时显示一致。

### 展示规则

| 条件（按优先级） | 展示与操作 |
|---|---|
| 来源扫描错误 | “无法导入”，显示原因，保持现有禁止操作行为 |
| 来源摘要或必要身份字段不可用 | “待核验”，提示重新扫描，不宣称内容一致 |
| 存在与 `import_sid` 及完整 `md5` 均一致的中央条目 | “已在中央库（摘要一致）”；来源不同仍允许预览合并来源 |
| 没有精确匹配，但该来源路径曾导入 | “来源与已导入版本不同”，允许预览导入为独立版本；不暗示自动覆盖正式版 |
| 其他情况 | “未导入”，保留预览导入入口 |

匹配应覆盖全部中央条目，不能只取同一路径的第一份历史版本。只有 UL 副本匹配、同内容不同名称、改名后保留原来源等情形，均按后端实际导入身份判定，不误报为可直接去重。摘要一致只表示与索引记录一致，不替代现有中央库漂移检查；不得据此禁用可读取来源的“预览导入”，中央副本缺失或漂移继续由既有导入校验拦截。

导入成功后刷新中央条目，并使来源缓存失效或重新扫描；扫描失败不得保留旧的“一致”状态冒充最新结果。新增 API 字段为兼容性增量，保留既有字段。

### 验收

- 路径与摘要都一致：显示已在中央库；仅修改附属脚本或可执行位后重新扫描：显示版本不同。
- 同一路径有多份历史版本：任一真实导入目标精确匹配时能正确识别，不受索引顺序影响。
- 同名不同内容、同内容不同名称、改名保留来源、只有 UL 匹配、相同版本来自另一 agent，展示与实际导入结果一致。
- 缺失摘要、扫描错误、重新扫描失败有明确状态；预览与取消不写中央库。
- 确认导入后状态刷新；来源文件保持不变。

## 阶段 3：切换分组前保护未保存修改（已完成）

### 实现方案

修改 `static/js/groups.js`，在渲染编辑器时冻结组名和成员集合为当前编辑基线；比较名称与成员集合判断是否未保存，成员顺序不作为修改。不能临时拿后台刷新后的 `S.data` 作为基线。新建分组也适用。

1. 组名输入和选择器增删成员后统一更新“尚未保存”提示；改回基线后取消提示。
2. 点击其他分组或“新建分组”时，先检测未保存修改。有修改则显示“继续编辑”和“放弃修改并切换”；默认继续编辑，Esc 也取消切换。
3. 用户明确放弃后才改变当前组并重绘。继续编辑时，名称、成员、选择器搜索及当前分组不变；重复点击当前组/当前新建入口不重置编辑器。
4. 复用 `ui.js` 内现有模态框实现，按需增加一个明确的确认函数；不使用浏览器 `confirm()`，不新增通用路由或表单管理框架。
5. 切换确认期间防重复处理。组级写操作从发起预览到预览/执行/刷新流程结束，局部锁住切换和重复写入，并捕获目标组与编辑器上下文，防止迟到结果清除另一组输入。预览请求使用名称与成员的提交快照；编辑器在整个异步流程中置为 `inert`/disabled，重绘后重新加锁，成功基线只采用该提交快照。创建/保存确认成功才更新基线；取消写入预览、校验失败或服务器错误均保留编辑内容。删除、拖拽若会舍弃当前编辑内容，先走相同离开确认；保留现有拖拽写入语义，不悄悄合并或保存其他未提交编辑。不借此重构所有页面的模态框。
6. 对手动刷新、页签返回和其他操作成功引起的 `renderGroups()` 重绘，在当前组上下文中保留一份内存编辑快照并恢复输入，避免只修切组按钮却仍在局部重绘时丢失修改。明确放弃、当前组成功保存/删除后清除对应快照；不扩展为全应用草稿系统，不承诺浏览器完整重载后的草稿恢复。

本阶段不自动保存，不写浏览器持久化草稿，不改变分发选择的保存规则。后台刷新、手动刷新或其他成功操作触发分组重绘时，只保留当前页内存快照。

### 验收

- 无修改正常切换；只改组名、只改成员、同时修改均能提示；成员改回原集合后不误提示。
- 已有组之间、新建到已有、已有到新建都覆盖；点击当前入口不丢输入。
- “继续编辑”及 Esc 保留全部编辑状态；“放弃修改并切换”仅丢弃当前未保存编辑，不发写请求。
- 保存预览取消、创建/保存失败不清空表单；保存成功后切换不再误提示。
- 快速重复点击不叠加确认、不切错目标；慢预览或保存返回时不误清另一组输入；取消/失败不得标记为已保存。删除/拖拽确认与后台刷新不绕过未保存检查；手动刷新、页签返回、分发成功重绘仍保留当前编辑。
